# **Обобщения (Generics) в C# — подробное и простое объяснение**

## **1. Что такое обобщения?**

Обобщения (generics) позволяют писать **универсальный код**, который работает с разными типами данных, **без приведения типов и ошибок времени выполнения**.

Пример без generics:

```csharp
object x = 10;
int y = (int)x; // нужно приведение, можно ошибиться
```

С generics:

```csharp
T — это «тип-переменная», которую мы подставляем позже
```

---

## **2. Обобщённый класс**

### **Простой пример: список для любых типов**

```csharp
class MyList<T>
{
    private T[] items = new T[10]; // массив для хранения элементов
    private int count = 0;         // количество элементов

    public void Add(T item) => items[count++] = item; // добавить элемент
    public T Get(int index) => items[index];          // получить элемент по индексу
}
```

**Использование:**

```csharp
MyList<int> numbers = new MyList<int>();
numbers.Add(5);
numbers.Add(10);
int x = numbers.Get(0); // x = 5

MyList<string> words = new MyList<string>();
words.Add("Hello");
words.Add("World");
string s = words.Get(1); // s = "World"
```

* `T` заменяется на **конкретный тип** при создании объекта.
* Можно использовать **любой тип данных**: int, string, свои классы.

---

## **3. Обобщённые методы**

Метод тоже может быть универсальным:

```csharp
class Utils
{
    public static void Swap<T>(ref T a, ref T b)
    {
        T temp = a;
        a = b;
        b = temp;
    }
}
```

**Пример использования:**

```csharp
int x = 1, y = 2;
Utils.Swap(ref x, ref y); // x = 2, y = 1

string s1 = "A", s2 = "B";
Utils.Swap(ref s1, ref s2); // s1 = "B", s2 = "A"
```

* `<T>` говорит компилятору: «я подставлю тип позже».
* Компилятор **автоматически понимает тип** по переданным параметрам.

---

## **4. Ограничения (Constraints)**

Иногда нужно, чтобы тип соответствовал определённым требованиям:

```csharp
class MyClass<T> where T : class, new()
{
    public T Create() => new T();
}
```

* `class` — T должен быть **ссылочным типом** (класс, строка и т.д.)
* `new()` — T должен иметь **конструктор без параметров**

Другие ограничения:

| Ограничение            | Что означает                                             |
| ---------------------- | -------------------------------------------------------- |
| `struct`               | Только **значимые типы** (int, double, struct)           |
| `class`                | Только **ссылочные типы**                                |
| `new()`                | Только типы с **публичным конструктором без параметров** |
| `where T : BaseClass`  | Наследование от конкретного класса                       |
| `where T : IInterface` | Реализация интерфейса                                    |

---

## **5. Несколько параметров типа**

Можно использовать несколько типов одновременно:

```csharp
class Pair<T1, T2>
{
    public T1 First;
    public T2 Second;
}

Pair<int, string> p = new Pair<int, string>();
p.First = 1;
p.Second = "One";
```

* `T1` и `T2` могут быть любыми типами.
* Очень удобно для «пары значений» или «ключ-значение».

## **6. Обобщённые интерфейсы и делегаты**

### **Обобщённый интерфейс**

```csharp
interface IRepository<T>
{
    void Add(T item);
    T Get(int id);
}

class UserRepository : IRepository<string>
{
    public void Add(string item) { }
    public string Get(int id) => "User"; 
}
```

### **Обобщённый делегат**

```csharp
delegate T Transformer<T>(T value);

int Square(int x) => x * x;

Transformer<int> t = Square;
Console.WriteLine(t(5)); // 25
```

## **7. Ковариантность и контравариантность (коротко)**

Используется для совместимости типов с обобщёнными интерфейсами и делегатами:

* **Ковариантность (`out`)** — позволяет использовать более производный тип.
* **Контравариантность (`in`)** — позволяет использовать более базовый тип.

Пример с интерфейсом `IEnumerable<out T>`:

```csharp
IEnumerable<string> strings = new List<string>();
IEnumerable<object> objects = strings; // можно, потому что out T
```

---

## **8. Главное о generics**

1. `T` — это **тип-переменная**, которую подставляем позже.
2. Generics позволяют писать **один код для разных типов**.
3. Обеспечивает **типобезопасность** и **повышает производительность**.
4. Можно добавлять **ограничения**, чтобы управлять типами.
