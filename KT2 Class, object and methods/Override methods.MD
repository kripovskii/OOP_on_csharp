# Переопределение методов в C# для начинающих

## Что такое переопределение методов?

Представьте, что у вас есть класс `"Животное"` с методом `"ИздатьЗвук()"`. Все животные издают звуки, но по-разному. Собака лает, кошка мяукает, а корова мычит. Переопределение методов позволяет каждому животному говорить своим голосом!

**Переопределение** — это когда класс-ребёнок меняет поведение метода, который он унаследовал от класса-родителя.

## Зачем это нужно?

1. **Полиморфизм** — одно действие, много реализаций
2. **Гибкость** — каждый класс может делать что-то по-своему
3. **Чистота кода** — не нужно писать много if-else проверок

## Как это работает? Три главных слова:

### 1. `virtual` — "можно менять"
Ставим перед методом в родительском классе. Говорит: "Эту функцию можно переопределить в детях"

### 2. `override` — "я меняю"
Ставим перед методом в классе-наследники. Говорит: "Я хочу сделать эту функцию по-своему"

### 3. `abstract` — "обязательно меняйте"
Для методов, у которых нет реализации в родителе. Говорит: "Дети, вы обязаны написать свою версию этого метода!"

## Простой пример

```csharp
// Родительский класс
class Animal
{
    // Виртуальный метод - можно переопределить
    public virtual void MakeSound()
    {
        Console.WriteLine("Какое-то животное издаёт звук");
    }
}

// Класс-наследник
class Dog : Animal
{
    // Переопределяем метод
    public override void MakeSound()
    {
        Console.WriteLine("Гав-гав!");
    }
}

// Ещё один класс-наследник
class Cat : Animal
{
    public override void MakeSound()
    {
        Console.WriteLine("Мяу!");
    }
}
```

## Как это использовать?

```csharp
Animal myAnimal = new Animal();
Animal myDog = new Dog();
Animal myCat = new Cat();

myAnimal.MakeSound();  // "Какое-то животное издаёт звук"
myDog.MakeSound();     // "Гав-гав!"
myCat.MakeSound();     // "Мяу!"
```

Вот что круто: все объекты имеют тип Animal, но каждый ведёт себя по-своему!

## Когда использовать abstract?

Когда в родительском классе невозможно дать разумную реализацию метода.

```csharp
// Абстрактный класс - нельзя создать его объект
abstract class Shape
{
    // Абстрактный метод - без реализации
    public abstract double GetArea();

    // Обычный метод
    public void Display()
    {
        Console.WriteLine($"Площадь: {GetArea()}");
    }
}

class Circle : Shape
{
    public double Radius;

    // Обязаны переопределить!
    public override double GetArea()
    {
        return 3.14 * Radius * Radius;
    }
}

class Square : Shape
{
    public double Side;

    public override double GetArea()
    {
        return Side * Side;
    }
}
```

## Важные правила

1. **Только виртуальные методы** можно переопределять
2. **Сигнатуры должны совпадать** — одинаковые имя, возвращаемый тип и параметры
3. **Нельзя сделать метод менее доступным** — если метод public в родителе, он должен остаться public в ребёнке

## Частая ошибка: new вместо override

```csharp
class Animal
{
    public void Sleep() { Console.WriteLine("Спит"); }
}

class Dog : Animal
{
    // НЕПРАВИЛЬНО! Это не переопределение, а сокрытие
    public new void Sleep() { Console.WriteLine("Собака спит"); }
}
```

Разница:
- `override` — меняет поведение для всех
- `new` — создаёт новый метод с тем же именем (лучше не использовать!)

## Практический совет

Начинайте с простого правила: если метод должен работать одинаково для всех — делайте его обычным. Если может работать по-разному — делайте virtual. Если не можете придумать общую реализацию — делайте abstract.

## Пример из жизни: система оплаты

```csharp
class PaymentSystem
{
    public virtual void ProcessPayment(double amount)
    {
        Console.WriteLine($"Оплата {amount} руб. через базовую систему");
    }
}

class CreditCardPayment : PaymentSystem
{
    public override void ProcessPayment(double amount)
    {
        Console.WriteLine($"Оплата {amount} руб. картой");
        // Здесь была бы реальная логика работы с картой
    }
}

class PayPalPayment : PaymentSystem
{
    public override void ProcessPayment(double amount)
    {
        Console.WriteLine($"Оплата {amount} руб. через PayPal");
        // Логика работы с PayPal
    }
}
```

## Итог

Переопределение методов — это как дать детям возможность делать что-то по-своему, но по общим правилам. Родитель говорит "что делать", а дети решают "как делать".

**Запомните:**
- `virtual` — "можно менять" (в родителе)
- `override` — "я меняю" (в наследнике)
- `abstract` — "обязательно меняйте" (в абстрактном классе)
