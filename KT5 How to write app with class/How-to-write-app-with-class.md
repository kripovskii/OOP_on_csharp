
# Практическое применение классов в C#

## 1. Классы как модель предметной области
Один из основных подходов — использовать классы для моделирования **объектов реального мира**.
То есть класс выступает как «цифровая копия» предмета или сущности, с которой работает программа.

### Подход
- Определяем свойства объекта (например, у книги — название, состояние «выдана/не выдана»).
- Добавляем методы, которые соответствуют действиям с этим объектом (взять, вернуть).
- Экземпляр класса — это конкретный объект (например, «Книга *Преступление и наказание*»).

### Пример
```csharp
public class Book
{
    public string Title { get; set; }
    public bool IsBorrowed { get; private set; }

    public void Borrow()
    {
        if (!IsBorrowed)
        {
            IsBorrowed = true;
            Console.WriteLine($"{Title} выдана читателю.");
        }
        else
        {
            Console.WriteLine($"{Title} уже занята.");
        }
    }

    public void Return()
    {
        IsBorrowed = false;
        Console.WriteLine($"{Title} возвращена.");
    }
}
````

### Когда применять

* В приложениях, где нужно описать сущности из предметной области: библиотека, интернет-магазин, CRM-система.
* Когда удобно думать категориями «объектов» и «действий над ними».

## 2. Классы как логика приложения (сервисы)

Иногда важнее не описывать объекты, а **организовать работу с ними**.
Для этого создают сервисные классы (или классы-менеджеры).

### Подход

* Класс не хранит состояние конкретного объекта, а инкапсулирует **процессы**.
* Методы описывают операции: создать заказ, отменить заказ и т. д.
* Такой класс работает как «рабочая станция» для выполнения бизнес-задач.

### Пример

```csharp
public class OrderService
{
    public void CreateOrder(string product)
    {
        Console.WriteLine($"Заказ создан: {product}");
    }

    public void CancelOrder(int orderId)
    {
        Console.WriteLine($"Заказ {orderId} отменён.");
    }
}
```

### Когда применять

* Когда есть бизнес-процессы, а не только данные.
* В архитектуре типа **Service Layer**: все операции идут через сервисы.
* Для отделения логики от интерфейса (например, GUI вызывает методы сервиса).

## 3. Классы как контейнер бизнес-правил

Класс может хранить состояние и одновременно **контролировать правила работы с ним**.
Например, не разрешать отрицательный баланс у клиента.

### Подход

* Храним данные в приватных полях.
* Управляем доступом через методы или свойства.
* Программируем правила: проверки, ограничения, валидацию.

### Пример

```csharp
public class Customer
{
    public string Name { get; set; }
    public decimal Balance { get; private set; }

    public Customer(string name, decimal balance)
    {
        Name = name;
        Balance = balance;
    }

    public void Buy(decimal price)
    {
        if (Balance >= price)
        {
            Balance -= price;
            Console.WriteLine($"{Name} купил товар за {price}. Остаток: {Balance}");
        }
        else
        {
            Console.WriteLine($"Недостаточно средств у {Name}!");
        }
    }
}
```

### Когда применять

* Если объект должен быть «самостоятельным» и защищать свои данные.
* Когда важно, чтобы состояние объекта всегда оставалось корректным.
* Для реализации бизнес-логики «внутри сущности».

## 4. Классы для организации программы

Классы помогают разделять **структуру программы**: одни отвечают за данные, другие — за управление ими.
Это делает код читаемым, расширяемым и поддерживаемым.

### Подход

* Создаём отдельные классы для сущностей (например, `Message`).
* Создаём отдельный класс-«контейнер» или «менеджер» (например, `Chat`).
* Класс-менеджер управляет коллекцией объектов и предоставляет методы работы с ними.

### Пример

```csharp
public class Message
{
    public string Author { get; set; }
    public string Text { get; set; }
    public DateTime Timestamp { get; } = DateTime.Now;

    public void Print()
    {
        Console.WriteLine($"[{Timestamp}] {Author}: {Text}");
    }
}

public class Chat
{
    private List<Message> messages = new();

    public void SendMessage(string author, string text)
    {
        var msg = new Message { Author = author, Text = text };
        messages.Add(msg);
        msg.Print();
    }
}
```

### Когда применять

* Когда приложение оперирует множеством однотипных объектов.
* Если нужно хранить историю, коллекции и управлять ими.
* При проектировании систем, где важна организация кода по слоям.

Сделайте мини-программу «Магазин»:

1. Класс `Product` с названием и ценой.

## Итог

Подходы применения классов в C#:

1. **Модель предметной области** — классы отражают реальные объекты.
2. **Логика приложения** — классы выполняют операции и бизнес-процессы.
3. **Контейнер бизнес-правил** — классы управляют собственным состоянием и защищают его.
4. **Организация программы** — классы структурируют код и делают его расширяемым.

Таким образом, выбор подхода зависит от того, что именно вы проектируете: данные, процессы или систему целиком.
