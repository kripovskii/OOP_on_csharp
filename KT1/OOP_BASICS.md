# Основные принципы ООП
Объектно-ориентированное программирование (ООП) строится на четырёх главных принципах:

* Инкапсуляция
* Наследование
* Полиморфизм
* Абстракция
###  Для чего нужны эти понятия?
* Инкапсуляция защищает данные и делает код безопаснее.
* Наследование позволяет не дублировать одно и то же, упрощает расширение.
* Полиморфизм делает код универсальным и гибким.
* Абстракция помогает мыслить категориями, а не деталями.
###  Вместе эти принципы позволяют:
* Писать код понятный для других людей,
* Делать программы гибкими и легко изменяемыми,
* Избегать ошибок при работе с данными,
* Экономить время на поддержке и развитии проекта.
---
## Инкапсуляция
**Смысл:** Скрываем внутренние детали, даём доступ только через определённые «двери» (методы).
**Из жизни:**

* Банкомат: ты не видишь, как работает база данных банка, но можешь нажать кнопки «снять» или «пополнить».
* Автомобиль: ты управляешь рулём и педалями, но не напрямую двигателем.

**В программировании:**

* В классе «Банковский счёт» нельзя напрямую менять баланс, можно только вызвать методы «пополнить» или «снять».
* В классе «Телефон» камера и микрофон скрыты — программист работает через функции «сделать фото» или «позвонить».

**Пример в программировании:**

* Класс «Банковский счёт» скрывает поле «баланс». Мы можем изменить его только через методы `снять()` или `пополнить()`.

**Схема:**

```
[ BankAccount ]
   ├── balance (скрыт)
   ├── deposit()
   ├── withdraw()
   └── getBalance()
```

##  Наследование

**Смысл:** Новый объект берёт свойства и поведение у существующего, добавляя своё.
**Из жизни:**

* Студент — это Человек, но дополнительно у него есть университет, экзамены.
* Электрическая машина — это Машина, но у неё есть батарея вместо бензина.

**В программировании:**

* Класс «Студент» может наследовать от класса «Человек», получая имя и возраст, и добавлять методы «сдавать экзамен».
* Класс «Админ» наследуется от «Пользователь» и имеет дополнительные права, например «блокировать других».

**Пример в программировании:**

* Класс «Студент» наследует от класса «Человек». У него уже есть имя и возраст, но добавляются методы «сдавать экзамен».

**Схема:**

```
[ Person ]
   ├── name
   └── introduce()

        ↓ наследует

[ Student ]
   ├── name
   ├── introduce()
   ├── university
   └── study()
```

## Полиморфизм

**Смысл:** Один и тот же интерфейс (действие) может работать по-разному в зависимости от объекта.
**Из жизни:**

* Слово «играть»:

  * ребёнок играет в игрушки,
  * музыкант играет на гитаре,
  * футболист играет в футбол.
* Кнопка «пуск»: в чайнике — вода кипит, в компьютере — включается система, в микроволновке — еда греется.

**В программировании:**

* Метод «вывести звук»:

  * у Кошки — «мяу»,
  * у Собаки — «гав».
* Метод «рисовать фигуру»:

  * у Круга — рисует окружность,
  * у Квадрата — рисует квадрат.

**Пример в программировании:**

* Метод `speak()` у класса «Животное»:

  * Собака → «Гав!»
  * Кошка → «Мяу!»

**Схема:**

```
[ Animal ]
   └── speak()

        ↓
  ----------------
  |              |
[ Dog ]       [ Cat ]
 speak() → Гав!  speak() → Мяу!
```

## 🧩 4. Абстракция

**Что это:**
Выделение общих характеристик и сокрытие ненужных деталей. Мы создаём «шаблон» (абстрактный класс или интерфейс), который описывает поведение, но не реализацию.

**Пример из жизни:**

* «Транспорт» — общее понятие: все перевозят, но конкретные детали (бензин, электричество, колёса) скрываются.
* «Животное» — все дышат и питаются, но каждый вид делает это по-разному.

**Пример в программировании:**

* Абстрактный класс «Фигура» имеет метод `draw()`. Конкретные классы (Круг, Квадрат, Треугольник) реализуют его по-своему.
* Интерфейс «Оплата» определяет метод `pay()`. Реализации: наличные, карта, криптовалюта.

**Схема:**

```
[ Shape ] (абстрактный)
   └── draw()

        ↓ реализуют
  ------------------------
  |           |           |
[ Circle ]  [ Square ]  [ Triangle ]
 draw()→ ○   draw()→ ▢   draw()→ △
```

# Примеры:

| Принцип          | Что значит                              | Из жизни                                          | В программировании                                     |
| ---------------- | --------------------------------------- | ------------------------------------------------- | ------------------------------------------------------ |
| **Инкапсуляция** | Скрываем детали, доступ через методы    | Банкомат скрывает базу, авто скрывает двигатель   | «БанкСчёт» скрывает баланс, есть только методы         |
| **Наследование** | Новый класс наследует свойства родителя | Студент — это Человек, электромобиль — это Машина | «Студент» наследует «Человека»                         |
| **Полиморфизм**  | Один интерфейс — разные реализации      | Слово «играть» → разные действия                  | Метод `speak()` работает по-разному у Собак и Кошек    |
| **Абстракция**   | Выделяем общее, скрываем детали         | «Транспорт» как шаблон, «Животное» как обобщение  | «Фигура» с методом `draw()` реализуется у разных фигур |
