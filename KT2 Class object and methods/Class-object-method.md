# Лекция: Классы, объекты, методы, поля и свойства в C\#

**Что в этой лекции:**

* Понятия **класса** и **объекта** (что это и зачем нужно).
* **Поля** — что такое, как используются, отличия и особенности.
* **Свойства** — зачем нужны, примеры, автосвойства и логика в сеттерах/геттерах.
* **Методы** — сигнатура, параметры, возвращаемые значения, побочные эффекты.

> Важно: в этой лекции мы **не** углубляемся в конструкторы, наследование, интерфейсы, делегаты и события. Фокус — только на перечисленных понятиях.

---

# 1. Класс — что это и как выглядит

**Класс** — это шаблон (описание) для объектов. Он описывает, какие данные (поля) объект будет хранить и какие действия (методы) он сможет выполнять. Класс сам по себе — **не объект**; объект появляется, когда мы создаём экземпляр класса.

Простейший пример класса в C#:

```csharp
public class Person
{
    // Поле — хранит состояние
    public string Name;

    // Приватное поле (внутреннее состояние)
    private int _age;

    // Свойство — управляет доступом к приватному полю
    public int Age
    {
        get { return _age; }
        set { if (value >= 0) _age = value; } // валидация
    }

    // Метод — действие, которое может выполнить объект
    public void SayHello()
    {
        Console.WriteLine($"Привет, меня зовут {Name} и мне {Age} лет.");
    }
}
```

**Разбор по частям:**

* `public class Person` — объявление класса с именем `Person`. `public` определяет доступность типа.
* Внутри класса есть **поля**, **свойства** и **методы**.

---

# 2. Поля

**Поле** — это переменная, объявленная внутри класса. Поля хранят состояние объекта.

Типичные моменты про поля:

* Поля бывают **публичными** (`public`), **приватными** (`private`) и с другими уровнями доступа (`protected`, `internal` и комбинации). Чаще рекомендуется делать поля приватными и открывать доступ через свойства.
* Есть **экземплярные** поля (хранятся в экземпляре объекта — у каждого объекта своё значение) и **статические** поля (одно значение на весь класс).
* Поля **ценных типов** (например, `int`, `double`, `struct`) хранятся как значения; полям ссылочных типов (например, `string`, `class`) присваивается ссылка на объект.

Примеры полей:

```csharp
public class Example
{
    public int PublicField;        // публичное поле (обычно не рекомендуется)
    private string _privateField;  // приватное поле (рекомендуется)
    public static int Counter;     // статическое поле — общее для всех экземпляров
}
```

**Детали и поведение:**

* Поля получают **значение по умолчанию**, если их не инициализировать явно: для `int` — `0`, для `bool` — `false`, для ссылочных типов — `null`.
* Если поле ссылочного типа равно `null`, попытка обратиться к его членам вызовет `NullReferenceException`.

**Почему публичные поля — плохо:**

* Открытые поля напрямую давят на внутреннюю реализацию класса: нельзя добавить валидацию при присваивании, нельзя изменить способ хранения данных, не ломая код клиентов.
* Свойства дают абстракцию и позволяют контролировать доступ.

---

# 3. Свойства

**Свойство** — это оболочка над полем (реже — вычисляемый член), которая предоставляет управляемый доступ к данным: чтение (`get`) и запись (`set`). Свойства выглядят как поле с внешней точки зрения, но по факту это методы доступа.

Простой пример свойства (с «ручным» бэкинг-полем):

```csharp
private int _age;
public int Age
{
    get { return _age; }
    set
    {
        if (value < 0)
            throw new ArgumentException("Возраст не может быть отрицательным");
        _age = value;
    }
}
```

**Автосвойства** — сокращённая запись, где компилятор сам генерирует скрытое поле:

```csharp
public string Name { get; set; }      // простое автосвойство
public int Id { get; private set; }   // публичный геттер, приватный сеттер
```

**Вычисляемые свойства** — возвращают значение на основе других данных, без отдельного поля:

```csharp
public int YearOfBirth { get { return DateTime.Now.Year - Age; } }
// или выражение-стиль
public int YearOfBirth => DateTime.Now.Year - Age;
```

**Особенности свойств:**

* Свойство — это пара методов `get`/`set`: при компиляции они превращаются в методы доступа.
* Можно задавать разные уровни доступа для `get` и `set` (например, `public get`, `private set`).
* Свойства удобны для инкапсуляции: в них легко добавить логику валидации, логирование, ленивую инициализацию и т.д.

**Когда использовать свойства, а когда поля:**

* Для внешнего API класса обычно используются **свойства**.
* Для внутренней реализации — **приватные поля**.

# 4. Объекты

**Объект** — это экземпляр класса: реальная сущность в памяти, создаваемая во время выполнения программы.

Как создать объект (коротко):

```csharp
Person p = new Person(); // создаём экземпляр класса Person
p.Name = "Иван";
p.Age = 30;
```

**Нюансы и поведение:**

* Переменная `p` содержит **ссылку** на объект (в случае ссылочного типа). Сама ссылка — значение; объект хранится в управляемой куче (heap).
* Если `p` равна `null`, она не указывает на объект.
* Несколько ссылок могут указывать на один и тот же объект:

```csharp
Person a = new Person();
Person b = a; // b и a указывают на один объект
b.Name = "Оксана";
Console.WriteLine(a.Name); // "Оксана" — изменение видно через обе ссылки
```

**Сравнение объектов:**

* Оператор `==` для ссылочных типов по умолчанию сравнивает ссылки (т.е. указывают ли они на один объект). Многие типы переопределяют `==` (например, `string`).
* Метод `Equals` можно переопределить для семантического сравнения (логического равенства).

**Сборка мусора:**

* В .NET объекты, на которые нет ссылок, со временем будут удалены сборщиком мусора (GC). Подробности работы GC — за пределами этой лекции, но важно знать: `new` выделяет память, освобождать её вручную обычно не нужно.

# 5. Методы

**Метод** — это функция, определённая внутри класса, описывающая действие или поведение объекта.

Типичная структура метода:

```csharp
[модификатор_доступа] [модификатор_статичности] возвращаемый_тип Имя(параметры)
{
    // тело метода
}
```

**Примеры методов:**

```csharp
public int Add(int a, int b)
{
    return a + b; // возвращаем значение
}

public void Print(string text)
{
    Console.WriteLine(text); // ничего не возвращает
}
```

**Ключевые моменты про методы:**

* **Сигнатура метода** включает имя и типы параметров. Возвращаемый тип не входит в сигнатуру для перегрузки.
* **Перегрузка методов**: можно объявить несколько методов с одинаковым именем, но разными параметрами.

```csharp
public void Log(string s) { /*...*/ }
public void Log(string s, int level) { /*...*/ }
```

* **Параметры** передаются **по значению** по умолчанию: для value-типов копируется значение; для ссылочных типов копируется **ссылка** (т.е. метод получает копию ссылки и может менять состояние объекта, но не может изменить внешнюю ссылку на другой объект).

  * Пример наглядно:

```csharp
public void ChangeName(Person p)
{
    p.Name = "Петя"; // изменит объект, на который ссылается p
}

public void Reassign(Person p)
{
    p = new Person(); // переопределение локальной копии ссылки — не влияет на вызывающую сторону
}
```

* Если необходимо, параметры можно передавать явно по ссылке с помощью `ref` или `out` (это отдельная тема).

* **Статические методы** (`static`) принадлежат классу, а не конкретному объекту. Вызываются как `ClassName.Method()`.

* **Экземплярные методы** вызываются на объекте: `obj.Method()`.

**Методы — побочные эффекты vs чистые функции:**

* **Чистая функция** не изменяет состояние и зависит только от входных параметров — её проще тестировать и понимать.
* **Метод с побочным эффектом** может менять поля объекта, вывод на консоль, работу с файлами и т.д.

# 6. Полный пример (всё вместе)

```csharp
using System;

public class Person
{
    public string Name;        // публичное поле (для простоты примера)
    private int _age;          // приватное поле

    public int Age             // свойство с валидацией
    {
        get { return _age; }
        set { if (value >= 0) _age = value; }
    }

    public void SayHello()     // метод: действие объекта
    {
        Console.WriteLine($"Привет, меня зовут {Name} и мне {Age} лет.");
    }
}

public class Demo
{
    public void Run()
    {
        Person p = new Person(); // создаём объект
        p.Name = "Иван";        // присваиваем поле
        p.Age = 28;              // через свойство (сработает проверка)

        p.SayHello();            // вызываем метод — действие

        // Передача ссылки в метод
        ChangeName(p);
        Console.WriteLine(p.Name); // выведет "Петя"

        // Переопределение локальной ссылки
        Reassign(p);
        Console.WriteLine(p.Name); // по-прежнему "Петя" — внешняя ссылка не поменялась
    }

    private void ChangeName(Person person)
    {
        person.Name = "Петя"; // изменяет состояние объекта
    }

    private void Reassign(Person person)
    {
        person = new Person();
        person.Name = "Кто-то"; // локальная переменная: не влияет на внешний объект
    }
}
```

**Пояснение к примеру:**

* `Person` содержит поле `Name`, приватное поле `_age` и свойство `Age` с проверкой.
* Метод `SayHello` показывает, как метод использует состояние объекта.
* В `Demo.Run` демонстрируется: создание объекта, присваивание полю и свойству, вызов метода, передача объекта в методы и эффект таких вызовов.

# 7. Ошибки и типичные ловушки

1. **Публичные поля вместо свойств.** Это ломает инкапсуляцию и затрудняет дальнейшую поддержку.
2. **Неинициализированные поля / null.** Всегда думайте о том, что ссылочные поля могут быть `null`.
3. **Ожидание, что присваивание внутри метода поменяет внешний указатель.** Присваивание параметру метода изменяет только локальную копию ссылки.
4. **Смешение ответсвенности (SRP).** Делайте методы небольшими и отвечающими за одну задачу.
5. **Неявные побочные эффекты.** Методы, которые меняют много полей объекта, сложнее тестировать.

---

# 8. Рекомендации и стиль

* Используйте **свойства** для публичного API класса; поля — приватные.
* Именуйте публичные типы и свойства в `PascalCase` (например, `Person`, `FirstName`), приватные поля — обычно `camelCase` с подчеркиванием `_field`.
* Предпочитайте **чистые** функции там, где это возможно — они проще для тестирования.
* Разделяйте логику: свойства должны выполнять простую валидацию и не содержать тяжёлых операций (I/O, длительных вычислений).

# Краткое резюме

* **Класс** — шаблон для объектов.
* **Поле** — переменная внутри класса, хранит состояние.
* **Свойство** — контролируемый доступ к полю (get/set), позволяет добавлять логику и валидацию.
* **Объект** — экземпляр класса, который хранится в памяти во время выполнения программы.
* **Метод** — действие/поведение объекта; у метода есть сигнатура, параметры и возвращаемый тип.
